第二域首步可写成代码实际对应的形式：

\[
\bar\theta=\theta-\alpha g_A,\quad
L_B^{\rm code}=\operatorname{CE}(f_{\bar\theta}(X_{S_A}),y_{S_B}),\quad
\theta_B^{\rm code}=\theta-\alpha\nabla_\theta L_B^{\rm code}.
\]

如果两个 loader 独立采样，损失中的 X 与 y 就不是同一组已标注观测。即使恰好类别相同，基点 θ 与 θ̄ 的区别也仍然存在。这里给出的是运行前的数据流反例，不需要先做一次大实验才能发现。

## 适配时的命名与验证边界

改变输入、回归头和位置划分后，称为论文机制的 UJI 适配；修复公开实现问题时同时保留原快照与小补丁。明确选择一阶还是二阶更新，不把两者混作同一个算法。

目标适应接口只接收 S 和明确授权的 U；评测接口另接收 Q 标签。先追踪作者 loader 中 `x_qry` 与 `x_test` 的实际来源，再决定 UJI 对应关系。若适配时把最终 Q 填入训练式 BatchNorm 的 `x_qry`，就新增了对评测特征的权限；不能把这个适配错误倒推为作者原协议泄漏。若改为冻结状态，先检查是否改变作者方法的工作条件。

后续最小验证应针对真正可出错的性质：打乱第二域标签时能够检查到配对错误；冻结模型对同一查询的预测不应因无关查询批次改变；更新方向与所选择的一阶/二阶公式一致；源任务位置拆分与目标评测定义一致。完成这些检查也只说明实现符合所选规格，不证明定位性能。
