# 开跑前反向审查（实现后、正式实验前）

日期：2026-09-30。对象为提交中的 `models/icl_context.py` 与 `scripts/evaluate_icl_context.py`。本文件在正式实验开始前写定；审查中的最小验证只用于检查结构，不是性能实验，也不改动预注册的常数。

## 1. 各阶段实际看到什么

| 阶段 | 输入 | 状态变化 | 不能看到 |
|---|---|---|---|
| 先验拟合 | 不含目标层的楼层对（trainingData） | ρ、β、θ、s、μ0、v_L0 | 目标层任何数据 |
| 合成上下文 | 旧层完整地图 + 先验 | 采样 3 条/坐标，随机流由 (楼层, K, episode, 方法) 固定 | 目标层 |
| 锚点 | K 位置 × 3 扫描（与 TPM 相同的 episode） | 追加到上下文，来源标记 1 | Query 坐标 |
| 上下文推断 | 上下文 + 查询 RSSI | 无参数更新 | 查询坐标（只在评价时读取） |

TabICL 的特征标准化、异常值裁剪、列筛选都只在上下文行上拟合，查询行只做变换，与部署一致。

## 2. 最小验证（结构检查，非性能）

1. **查询之间是否相互影响。** 同一上下文下，查询单独预测与跟另一批查询叠在一起预测，最大差异 6.8×10⁻³ m；打乱查询顺序、重复调用的差异为 0。批内不是严格独立（推断按批计算的微小数值差），对 MDE 的影响可以忽略。validation 与同日 Query 放在同一批预测不会互相泄漏标签，因为查询行的坐标从未输入。
2. **合成先验与 TPM 是同一个先验。** 由 `latent_prior` 重算 E[x_imp] 与 `prior_map` 的差异小于 1e-10（单元测试）。
3. **来源标记是否被 TabICL 预处理破坏。** 标记列只有 0/1 两个值；异常值裁剪在 K=3（339 合成 + 9 锚点）时把 1 压到 0.693，但锚点行与查询行变换后取值相同，区分信息保留。
4. **先验检出数的校准（诊断，不修正）。** 合成扫描每条的平均检出 AP 数与真实上层扫描相比：B0F2 22.0 对 17.4、B1F2 26.4 对 18.3 明显偏多，B2F1 14.0 对 20.2 偏少，其余接近。检出值均值偏差在 ±6 dB 内。这与后验预测检验中"高端检出率偏高约 0.1"一致。它会使合成行的"检出指纹"与查询系统性不同，是 H1/H4 可能不成立的具体机制；已在推导 §4 列为风险，按预注册不做修正。

## 3. 能退化成什么、不能解决什么

- 无先验行时，主方法退化为"仅锚点 ICL"（即 RNP-UJI 中的 TabICLv2 基线）。
- 没有标记列时，模型无法区分合成与真实行；这是独立变体，用来检验标记的作用。
- 上下文行数最多约 400，远低于 TabICL 的规模限制，不需要截断或检索。
- 输出可以超出候选凸包；无法按楼层几何约束预测。
- 本轮不回答"跨时间、跨设备"的变化，只和 TPM 在同样的数据权限下比较。

## 4. 结论

结构上没有发现数据权限或训练/测试路径不一致的问题；已知的先验检出偏差按预注册保留，只在结果中诊断。可以按冻结协议运行。
