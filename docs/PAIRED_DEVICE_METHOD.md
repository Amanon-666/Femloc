# 在相同空间覆盖上学习跨设备定位

## 为什么重定源任务

上一版把 Support 设备和 Query 设备分开，却允许两台设备各自只在不同区域有数据。B1F2、B2F0、B2F1 的真实 Query 至最近 Support 距离因此显著增加；这不是单独的设备变化实验。七个源楼层都至少存在一对手机，在共同的 20 个以上位置各采到至少 5 条不同 RSSI 指纹，足以重建受控的异位置任务。

## 固定任务与方法

每次从一个源楼层选择两台手机，先取得**两台手机都采过**、第一台每位置至少 3 条、第二台至少 5 条不同指纹的共同位置；只有共同位置数至少 20 的手机对可选。再随机选 20 个共同位置：10 个位置×3 条来自第一台作为 Support，另外 10 个位置×5 条来自第二台作为 Query。PhoneID 只供源 episode 采样，不输入网络，也不用于挑选目标 Support。

网络、线性求解、损失、七个源楼层、三开发楼层、三探索目标、三个 seed、1500 源更新、开发选轮、10×3 目标标注及全部目标 manifest 均沿用 `support-conditioned`。这次只修改源任务的采样条件；不加入对比损失、核、数据增强或目标域参数。若其收益仍不稳定，下一步应重审学得表示与 AP/时间变化，不继续按目标楼层堆采样例外。

与旧方法同划分配对比较，主指标仍是未采集位置误差；官方 validation 同时包含多种变化，只作为探索性混合场景。所有目标楼层已在先前研究中查看，不构成独立确认集。
