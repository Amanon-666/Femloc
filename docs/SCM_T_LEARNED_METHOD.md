# 在已有效的 SCM-T 地图上学习 AP 可靠度

## 方法判断（训练前冻结）

双通道学习首轮在整栋留出官方 validation 上为 12.66 m，冻结同一地图为 15.72 m，但已有 SCM-T 为 10.98 m。训练确有作用，不能证明拆分地图比原有地图更好。因此本对照只检验：**保持现有 SCM-T 地图和候选不变，直接训练 AP 的检出证据权重和数值不确定度，是否能进一步降低定位误差。** 这不是把第一轮的坏楼层加专属处理。

## 可执行定义

继续用 `SCM-T` 原来的 `−110` 编码平均指纹及 `ℓ=60,λ=.3` 空间残差更新，保留同一批旧图坐标与 Support 原型候选。编码值 V 不解释成条件 RSSI 均值。每个候选–AP 输入为：旧地图真实检出频率、`Φ((V+80)/16)`、旧编码强度和更新后编码强度的 `(v+110)/110`、锚点 GP 覆盖度、编码修正绝对值/50、在十个 Support 坐标被看到的比例。

沿用相同 `7→16→2` AP 共享网络，输出正的 b 和 σ，再学习一个正温度 T。参数 163 个，初值为 `b=1,σ=16,T=1`。

`score_j = −Σ_{a检出} [(x_a−V_ja)²/(2σ_ja²)+log σ_ja] + Σ_{a未检出} b_ja log Φ((−80−V_ja)/σ_ja)`。

归一化 `softmax(score/T)` 输出候选坐标均值。冻结初值与原 SCM-T 完全同义：`log16` 对每个候选相同，可从 softmax 中抵消。检查脚本实际比对输出。

“学习”改变 AP 的证据可靠度，不改变虚拟地图坐标、信号值、候选集合或目标标注量。检出率和强度的上下文按同 AP 聚合，这是从 GUFU 借来的关系表示思想；没有重新声称运行 GUFU 的不完整 GNN 快照。

所有训练、模型种子、600 步预算、建筑等权抽样、三折整栋留出及 target manifest 与第一轮完全相同。Config `configs/scm_t_learned.json`，入口仍为 `scripts.run_learned_ap_map`；输出 `outputs/scm_t_learned_v1`。第一轮输出和报告保留。

主要对比是 frozen SCM-T 与 learned SCM-T 的配对 MDE；源开发曲线不负责挑步数。允许官方 validation 改善或退化，如实记录，不因此改阈值、核或楼层专属参数。
