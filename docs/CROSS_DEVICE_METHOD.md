# 用源楼层的跨设备任务训练少标注定位表示

## 判断

上一版在 trainingData 内的异位置评价取得部分收益，但在 B2F3 官方 validation 退化。其源 episode 随机抽扫描，Support 与 Query 各自总是混有多个设备，网络只需处理平均意义上的混合分布；并未被明确要求“用设备 A 的标注，在设备 B 的未见位置预测”。源楼层中每层都至少有两台设备各自覆盖 20 个以上可提供每点 3/5 条不同指纹的位置，因此可以构造该训练任务。官方 validation 同时变化了时间、用户和 AP 状态，设备不是唯一解释。

## 唯一方法修改

沿用旧分支的 `520→256→128` 编码器、Support 上直接求线性坐标映射、异位置 Query 损失、10 位置×3 扫描目标预算、七个源楼层、开发/探索目标划分、1500 源更新与正则参数。仅改变**源 episode 的采样条件**：

1. 从一个源楼层选择两台不同的手机；每台都要有至少 20 个位置、每位置至少 5 条不同指纹。
2. 第一台手机在 10 个位置各提供 3 条带坐标扫描作为 Support。
3. 第二台手机在另外 10 个位置各提供 5 条带坐标扫描作为 Query。
4. 编码器只输入 RSSI，绝不输入 PhoneID；PhoneID 只用于源端采样。目标端 Support、Query 和官方验证完全沿用旧划分，不按设备筛目标样本。

不同设备的扫描分布若有差异，源端只有学到可在两台设备间使用的空间表示，才能降低异位置 Query 误差。这是训练任务分布的修改，不是为 B2F3 单独加修正系数。由于设备和采集区域可能相关，训练若变差，也不能直接断言设备不重要。

## 固定比较

目标与旧分支逐个 seed、episode 使用同一个 manifest，比较训练特征＋岭回归的配对差，同时保留随机特征、原始 RSSI 岭回归和 WKNN。开发楼层选择训练轮数，探索目标只评分。因这些楼层与官方 validation 已反复查看，结果仅用于方法诊断，不宣称独立确认。
