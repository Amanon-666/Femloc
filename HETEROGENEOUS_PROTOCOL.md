# UJI adaptation of AISTATS 2025 task-specific regularization, before formal experiment

Question: can a source-learned rule for assigning per-AP ridge regularization help a new building, and does actual AP-specific matching contribute beyond its average regularization strength?

Method source: Tomoharu Iwata, Atsutoshi Kumagai, Yasutoshi Ida, Meta-learning Task-specific Regularization Weights for Few-shot Linear Regression, AISTATS 2025. https://www.kecl.ntt.co.jp/as/members/iwata/aistats2025linear.pdf ; author code https://www.kecl.ntt.co.jp/as/members/iwata/code_meta_linear.tar.gz . The unmodified author module is loaded from a private external directory and is not vendored/pushed. Its license permits internal noncommercial evaluation and prohibits modification/distribution. The adapter uses existing public submodules to obtain regularization weights and implements the paper's dual ridge formula, never calls a Query-label-dependent prediction interface. Public code/results exclude the proprietary module and checkpoints.

Forward task: inputs are RSS fingerprints, outputs are 2D coordinates on a known floor. This is inverse few-shot localization, not old-map maintenance. No AP physical coordinates, old target map, or Query coordinates are used. AP IDs only establish correspondence between columns within the current task. Network parameters have no AP-specific index.

RSS transformation is fixed 100->0 and otherwise (RSS+105)/105. X is not centered or standardized from target data. Only AP columns nonzero in current Support are retained, for both encoder and ridge; Query never determines the retained columns. This avoids arbitrary numbers of inactive tokens in attention. For zero prior mean ridge, a Support-all-zero AP has coefficient exactly zero, so retaining its Query-only values cannot supply an identified coordinate direction. Dropping inactive tokens does change the attention context from 520 fixed tokens and is an explicit adaptation.

Response Y = (coordinate - Support coordinate mean) / source RMS coordinate scale. Source scale excludes the held building. Both centered coordinate values enter the encoder as target-type tokens. Every AP value and every target-coordinate value is paired with a 0/1 feature/target type indicator. Author f_xym and f_z encode the Support tensor N×(activeAP+2)×2. Each of three author MatrixAttentionEncoder blocks performs a global N×N sample attention (q/k concatenate all variables) followed by a global (AP+2)×(AP+2) variable attention (q/k concatenate all samples). All transformations share parameters across APs. Author f_mub gives each AP log lambda, f_a0/f_a1 generate a global bias log lambda. This follows the author's six attention stages; it is not independent per-AP ordinary attention. Hidden=128, heads=4, author implementation uses its internal n_embed=32. Two-output shared-lambda regression follows Appendix multi-target extension, not original scalar benchmark scores.

Lambda = exp(log lambda).clamp(min=1e-3), including bias. The clipping is original author code and gives zero gradients at its lower floor; saturation will be reported, not silently changed. use_mu=0 selects paper's primary zero coefficient-prior-mean model; author CLI default use_mu=1 is the optional Appendix prior-mean model. There are no unconstrained target-specific AP parameters. The coefficient vector is obtained by sum-SSE weighted ridge, W = Lambda^-1 X^T (I + X Lambda^-1 X^T)^-1 Y with a constant-one bias column. The author's code and Eqs10/11 use sum SSE without N lambda despite Eq9 printing 1/N. All ridge controls follow the code's same sum convention. Positive bias regularization is kept throughout, not replaced by an unpenalized intercept.

Prediction restores Support mean and source scale. Linear ridge coefficients may have negative signs; predictions can extrapolate beyond the Support convex hull. This is not a WKNN restriction. The learned lambdas are conditional regularization rules, not measured physical AP positions. Support-label-dependent empirical regularization does not imply a calibrated generative GP posterior.

Four methods: full feature-specific lambdas; flatten all AP lambdas to their geometric mean while preserving the same predicted bias lambda; deterministic shuffle AP lambdas without shuffling columns, preserve bias lambda; source-development-selected scalar ridge with equal AP/bias lambda. Full, flatten and shuffle use exactly the same source-selected final checkpoint; these are conditional inference ablations, not separately trained scalar/shuffle models. Scalar ridge is a practical whole-model comparator with tied bias, so AP-specific attribution rests on same-checkpoint controls. Permutation seed 12345+draw is fixed before scores. AP-rename invariance refers to full, not deliberately mismatched shuffle.

Outer source training: position-separated Support and Query episodes from source floors; K uniformly 3/5/10/20 physical positions, 3 unique scans per point, Query30 other positions×1 scan. Rotation/reflection acts only on source coordinate labels. Source Query MSE averaged over the two axes trains encoder/lambda rules through the closed-form coefficient solve. Source Query labels only enter this outer loss, not the lambda generator. Adam1e-4, zero weight decay/dropout, one episode per update. This is a bounded UJI adaptation, not the paper's 5000-epoch/32-task-batch full benchmark.

LOBO source selection: two other buildings only, their highest floors held for source development. Full model chooses between 300/1000 updates by fixed source-dev MDE; flatten/shuffle keep that exact choice. Scalar lambda grid .001,.01,.1,1,10,100 chosen only on source dev. Refit the chosen full schedule on all permitted source floors with the same seed. Two seeds and three held buildings, with a maximum 12000 source updates counting development+refit. No target score may expand training or change settings. The previous frozen ADKF manifest is reused exactly for target nested K and both position-isolated/internal and official Query. Raw GP/DKT results serve prior contextual references, not newly tuned controls.

Reverse audit: target output -> restored mean/scale -> Q RSS times fitted W -> W depends only on Support RSS/labels and positive lambdas -> lambdas depend only on Support values and frozen source network -> network/scale/checkpoint decisions come only from other buildings. Every evaluation recomputes current-task W and lambdas, no cross-task cache or previous target task state. Query inputs cannot modify either lambdas or W. Target Query coordinates exist only to calculate final errors. The same active Support columns, bias treatment, scaling and row-ID manifest apply to all four methods.

Counterexamples/boundaries: empty Support cannot define a coordinate center and is excluded by K>=3; one physical anchor (even with repeated scans) has centered Y=0, hence W=0 and zero lambda gradient, and predictions equal the anchor. A Support-all-zero AP also has W=0. A nonzero constant AP can receive nonzero W because it is collinear with the bias; its Query variation is not identified from Support. Identical AP columns in all Support are indistinguishable: their lambdas and coefficients are equal under the shared equivariant policy, even if true Query effects differ. AP new to source but observed in Support is the actual reusable-rule case, whereas Query-only AP is informationally unsupported. Strongly nonlinear RSS geometry is not made linear by regularization. Duplicate/conflicting RSS, weak position coverage, and few independent source environments remain limitations.

Source-only verification completed before formal training: adapter MSE vs unchanged author's original forward is exactly equal for 1 and 2 targets; AP common renaming/Support row permutation differences ≈4.4e-16; query-only AP/zero Y boundary holds; finite difference of lambda gradient error≈1.7e-10. Source25 updates take about4.1s on CPU2 threads with no target evaluation. This runtime suggests at most~33min training plus evaluation for the planned maximum, subject to source episode active-AP sizes. Full vs flatten/shuffle outperformance consistently across source-held buildings would support useful AP matching; flat/shuffle indistinguishable would fail that mechanism claim even if overall ridge scores improve. Inferior mean error vs scalar ridge/raw GP means source-learned regularization has not established practical value under this protocol; it is not grounds for target-guided retries.
